# Contributing

Use the Bun and Node versions recorded in `.bun-version` and `.node-version`. Install at the repository root with `bun install --frozen-lockfile`, copy `.env.example` to `.env`, then run `bun run db:migrate`, `bun run db:seed`, and `bun run dev`. Stop both processes with Ctrl+C. The root dev command supervises both; do not run a second API against the same SQLite file.

Edit a TypeScript file under `apps/web/src/routes` to add a page. Start generates the route tree during dev and build. `bun run check:web` generates it before typechecking, so a fresh clone needs no prior dev session. `routeTree.gen.ts` is ignored and never edited by hand. Route identifiers inside `createFileRoute` must match the filename and stay literals for the generator.

Edit `packages/db/src/schema.ts` to change persistence; it is the only place tables live. Run `bun run db:generate`, inspect the SQL, commit its migration and metadata, then run `bun run db:migrate`. Schema edits and generated migrations go in the same PR. Migrations have one operator at a time; app startup never migrates. Never use `drizzle-kit push` against shared data. Tests use committed migrations, so a stale schema change fails its focused behavior test.

The seed (`packages/db/src/seed.ts`) inserts one row at a reserved development fixture key and ignores conflicts. A second run preserves any existing row. It does not clear tables. Seed only your local development database. `DB_PATH` resolves against the root; the directory is created on first open. `.env` and `.data/` are ignored.

Write request work in `apps/api/src/features` as Effect programs: yield services such as `Database`, wrap each Drizzle call in `Effect.tryPromise` with a tagged error, and run the program once in the route with `runRequest`. Declare `internalServerErrorResponse` beside each route's success response. Add a service by extending the layer in `apps/api/src/runtime.ts`; nowhere else provides services or runs programs. Scripts and config stay plain async TypeScript.

Add focused Vitest tests next to the feature or table, one behavior per test. API tests construct `createApp` and call `app.handle`; every database test gets its own migrated memory connection via `createTestDatabase()` from `@hackmidwest/db/testing`. Close it in `finally`. Web tests render components with Testing Library. API tests run in Node fork workers using libSQL, never `bun:sqlite`. Vitest is the unit test runner; do not add a competing Bun test suite.

Before opening a PR, run `bun run fix`, `bun run lint`, `bun run check`, `bun run build`, and `bun run test`. CI runs two jobs: static checks (format, lint, typecheck, build) and unit tests. Dependency versions are exact; commit `bun.lock` with every dependency change and rerun all checks. Use conventional commit messages. Agent-written PRs identify the model, provider, and reasoning effort (e.g. `## Model: Claude Code (Opus 5.5) Reasoning: low`), then describe the change and validation clearly.

The web app may import API types only through `@hackmidwest/api/contract`, and never imports `@hackmidwest/db`. Do not add a relative import into API source or a duplicate shared Task interface. Package export conditions reject runtime imports, and Biome rejects relative server imports. Eden is the only HTTP client for application endpoints. Elysia is present in the web dependency graph because Eden declares it as a peer; application code never imports an Elysia runtime value there. `bun run lint` enforces these boundaries with dependency-cruiser (`.dependency-cruiser.ts`); a violation prints the rule name and the full import chain. When you add or change a rule, add a probe to `test/module-boundaries.test.ts`. Only entry points (`apps/api/src/index.ts`, `packages/db/scripts/`) read `process.env` or import `openDatabase` from `@hackmidwest/db/connection`; everything else receives config or `db` as a parameter. API and database source also runs on Node under Vitest, so it never uses the `Bun` global; only the Bun entry point `apps/api/src/index.ts` may.

React Compiler memoizes components and hooks automatically (`apps/web/react-plugins.ts`, shared by the build and tests). Don't add `useMemo`, `useCallback`, or `memo` for performance; reach for them only when a stable identity is required for correctness, such as an effect dependency.

On pull requests, autofix.ci runs `bun run fix` and commits the result to your branch. Pull before pushing again. Only safe Biome fixes are applied; anything else still fails `lint` and needs a manual change.
